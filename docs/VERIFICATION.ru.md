Среда: Windows x64, Temurin JDK 25.0.4.1+1, Gradle 9.2.1,
Minecraft 26.2, NeoForge 26.2.0.81, ModDevGradle 2.0.146.

- `build`: Java-код компилируется, мод собирается в JAR.
- JUnit: **23 теста**, 0 ошибок, 0 пропусков.
- Python: **15 проверок** геометрии, UV, направления ствола, параметров и рецептов.
- Выделенный Minecraft GameTest server: **61 тест Techguns + 1 встроенный**,
  все 62 прошли. Последний локальный запуск: 2026-09-08 00:02 Europe/Zurich.
- Все **55 рецептов** действительно загружаются через Minecraft RecipeManager;
  в последнем журнале нет ошибок разбора данных.
- Предыдущая сборка запускалась пользователем в клиенте Minecraft 26.2. После запрета
  управления рабочим столом новые изменения проверяются только без окон.
- Каталог исходников: 761 Java-файл, 103043 строки, 2133 ресурса, 44 записи оружия.
- Дерево `legacy/1.12.2/src` побайтово совпадает с Git-деревом `src` исходного
  репозитория: оба имеют ID `270b27b1cc52019733bb79facda68ce29aa038be`.
- Генератор преобразует **493 детали 17 моделей** и формирует **313 файлов**:
  параметры, Java-каталоги, cuboid/OBJ, материалы, ресурсы, теги и рецепты.
- Ресурсный граф: **53 item definitions, 78 ссылок на текстуры, 31 звуковое событие**.

GameTests проверяют:

- Для каждого из 17 образцов: реестр, перезарядку, сериализацию магазина, выстрел,
  число снарядов, исходные параметры пули и блокировку повторных запросов.
- Сохранение боезапаса; 45 тиков перезарядки револьвера; отмену при смене предмета,
  включая другой экземпляр того же типа; повторную проверку наличия патронов.
  Смена оружия не позволяет обойти общий cooldown. Недопустимые действия отклоняются.
- Попадание в сущность, защиту каменной стеной, время жизни, гравитацию ручной пушки,
  запись/чтение пули. Все восемь дробин наносят урон в одном тике.
- Возврат пустого магазина и целых остатков; загрузку дроби из нескольких стеков.
- Исходную формулу брони: при 10 единицах защиты и пробитии 0,5 урон винтовки —
  10,88; toughness 2 снижает его до 9,6.
- Восемь сценариев прицела: поддержка оптики, отмена перезарядкой/сменой стека/смертью,
  центрированная точка вылета, отсутствие доверия к поддельному флагу HUD,
  исключение временных флагов из NBT и однобайтовый сетевой codec.
- Загрузку всех 55 рецептов; изготовление деталей, ручной пушки, револьвера и патронов;
  заряженный/пустой Thompson; пять типов магазинов с последующей R-перезарядкой;
  упаковку/распаковку патронов и металлов без изменения количества.
- Позолоту при 0, 3 и 6 патронах с сохранением имени, независимостью входного стека
  и исключением флагов действий; сетевую сериализацию особого рецепта. Выбор
  предпочтительного тега и fallback при отсутствии материала проходит codec round trip.

Рецептные тесты используют реальные `matches`/`assemble` и серверную логику оружия.
Они не проверяют управление экраном верстака, shift-click или получение свинца и
стали из руд: генерация руд и станки ещё не перенесены.

Проверка журнала выявила, что старое поле `type` для особого ингредиента не подходит
NeoForge 26.2: два рецепта SCAR пропускались, несмотря на остальные зелёные тесты.
Исправлено на `neoforge:ingredient_type`; добавлен отдельный тест присутствия каждого
сгенерированного рецепта в настоящем RecipeManager. Повторный запуск прошёл без этих ошибок.

## Что выявил запуск клиента

В первом запуске отсутствовали две текстуры: старые пути `guns/` и `items/`
не попадали в современный атлас. Генератор исправлен на `textures/item/` и
ссылки `techguns:item/...`; исходные PNG сохранены без изменения.

Полная визуальная перепроверка после исправления **не завершена**: пользователь
остановил Computer Use клавишей Escape и запретил дальнейшее управление рабочим столом.
Этот запрет сохранён в `AGENTS.md`; дальнейшие проверки выполняются без окон.
Пользователь затем сообщил, что оружие направлено обратно. Повороты обеих рук
исправлены, координаты UV при отражении пересчитаны. Направление ствола, сохранение
углов, диапазоны координат и соответствие UV исходным вершинам проверяются без UI.
Вид в creative, окончательные позиции в руках, звук в игровом мире и клиентские
анимации всё ещё требуют визуальной приёмки; она не заменяется математическими тестами.

В журнале также присутствует ошибка OSHI при чтении счётчиков Windows Perflib.
Она не помешала запуску окна Minecraft. Системные настройки не изменялись.

  по сети, reconnect, многопользовательскую синхронизацию или нагрузочное тестирование.

  сетевые пакеты и анимация этими тестами не проверены.
